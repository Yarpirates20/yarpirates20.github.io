I've become interested in programming simulations for fun. The first one I've ever made was [Conway's Game of Life](https://github.com/Yarpirates20/ConwaysGameOfLifeRemix) three years ago, which I made using some Windows API but will probably want to redo using something like SFML, which I used in the L-System project. 

A short overview of what an L-System is, from Wikipedia:

> An L-system consists of an alphabet of symbols that can be used to make strings, a collection of production rules that expand each symbol into some larger string of symbols, an initial "axiom" string from which to begin construction, and a mechanism for translating the generated strings into geometric structures.

I was really drawn to the recursive replacing of an symbol with a similar one. Seems similar to a spiral of thoughts. So you wind up generating a repeating pattern in a string, and then use turtle graphics to draw them. You can change the symbols, rules, and the angles to draw to get a variety of different trees/fractals. Below are some examples and their characteristics.

### Sierpinski triangle
- **axiom**: F-G-G
- **rules**: (F -> F-G+F+G-F), (G -> GG)
- **angle**: 120°

![f-g-g](assets/images/l-system/f-g-g-angle-120.png)

### Fractal Plant
- **axiom**: -X
- **rules**: (X -> F+[[X]-X]-F[-FX]+X), (F -> FF)
- **angle**: 25°

![-x](assets/images/l-system/-x_angle_25.png)

I have played around with SFML before, but not since before SFML 3.1. I had never used SFML with CMake either. I have been using CMake fairly regularly since it's pretty easy to pull in libraries with Fetch-Content. The learning curve is a bit steep for CMake, so I was glad to discover the [SFML CMake Template](https://github.com/SFML/cmake-sfml-project) which made including SFML in a project so easy. 

I think I can see some areas of improvement with my L-System project, such as a user facing input for axioms and rules, which I did not consider at the time. This was just a quick summer-break starting project, and I have started working on creating Boids, which simulates flocking behavior. That is more complicated, but hopefully I'll put it up sometime soon.

Check out the source code for this project on my [Github](https://github.com/Yarpirates20/l-system#sierpinski-triangle).
